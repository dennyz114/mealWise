# MW-005 — Technical Plan: Internationalization (i18n)

## Technical Details

### Overview
Implement multi-language support (English, Spanish, French) using a lightweight React context approach. No external i18n library — just a custom hook, translation files, and a context provider. The language picker lives in the ProfileDropdown.

### Approach
1. **Translation files** — JSON files in `src/locales/` for each language, organized by domain
2. **Language context** — React context providing `locale`, `setLocale`, and `t()` function
3. **Custom hook** — `useTranslation()` returns `{ t, locale, setLocale }`
4. **localStorage persistence** — Same pattern as theme and sidebar preferences
5. **Default language** — Spanish (ES) for new users
6. **Language picker** — Inline expandable section in ProfileDropdown

## Files to Create/Modify

### 1. `src/lib/i18n.ts` — Core i18n logic
Contains:
- `LANGUAGES` constant array with locale code, English name, native name, flag
- `LOCALE_STORAGE_KEY = 'mealwise-locale'`
- `DEFAULT_LOCALE = 'es'`
- Type definitions for translation keys

```ts
export const DEFAULT_LOCALE = 'es'
export const LOCALE_STORAGE_KEY = 'mealwise-locale'

export const LANGUAGES = [
  { code: 'en', name: 'English', nativeName: 'English', flag: '🇺🇸' },
  { code: 'es', name: 'Spanish', nativeName: 'Español', flag: '🇪🇸' },
  { code: 'fr', name: 'French', nativeName: 'Français', flag: '🇫🇷' },
] as const

export type Locale = (typeof LANGUAGES)[number]['code']
```

### 5. `src/hooks/useTranslation.ts` — Translation hook
Custom hook providing translation function and locale state.

```ts
type TranslationContextValue = {
  locale: Locale
  setLocale: (locale: Locale) => void
  t: (key: string) => string
}

const useTranslation: () => TranslationContextValue
```

Logic:
- Read locale from context
- `t(key)` looks up nested key in current locale's translation file
- Falls back to English if key not found in current locale
- Falls back to key itself if not found in English either

### 6. `src/components/TranslationProvider.tsx` — Context provider
Wraps the app with translation context:
- Initialize locale from `localStorage` (default: Spanish)
- On locale change, update `localStorage` and `document.documentElement.lang`
- Load translation files (can be static imports since we only have 3 languages)

## API Contracts

### `useTranslation()` Hook
```ts
type Locale = 'en' | 'es' | 'fr'

type UseTranslationReturn = {
  locale: Locale
  setLocale: (locale: Locale) => void
  t: (key: string) => string
}

const useTranslation: () => UseTranslationReturn
```

### `TranslationProvider` Component
```tsx
type TranslationProviderProps = {
  children: React.ReactNode
}

const TranslationProvider: React.FC<TranslationProviderProps> = (props) => JSX.Element
```

## Essential Tests

### Frontend

1. **Default Language**
   - New users see Spanish UI by default
   - First visit with no localStorage shows Spanish

2. **Language Switching**
   - Selecting English changes all UI labels to English
   - Selecting Spanish changes all UI labels to Spanish
   - Selecting French changes all UI labels to French
   - Language change is immediate (no page reload)

3. **Persistence**
   - After switching to English, refreshing page keeps English
   - After switching to French, refreshing page keeps French

4. **Language Picker**
   - Collapsed state shows current language code badge
   - Clicking expands to show all language options
   - Selected language has checkmark icon
   - Clicking a language selects it and collapses options
   - Language row has accent color

5. **Translation Coverage**
   - Navigation items (Meals, Planner, Shopping) translate
   - Profile dropdown items translate
   - Placeholder pages translate

6. **Fallback**
   - Missing translation key falls back to English
   - Missing English key falls back to the key string itself

### Backend
No backend changes required — i18n is purely frontend.
